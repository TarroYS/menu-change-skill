## FILES
Raw Gsheet(.xlsx,40+ tabs,3-row hdr,JSON root rows) · Menu Preview(price+dish_code+modifier tabs, from action1) · OCR Output(preview+paper prices) · Price Comparison Report(deliverable).
Report tab order: **Summary, Dish Item, Questionnaire, Price Inference, Modifier Summary, Modifier Rule, Fried Specialty, Dish Code** (hidden Modifier last). Edit-source tabs (Dish Item, Modifier Summary, Modifier Rule) colored RED. Purple cells on Dish Item = inferred (not printed) — callback items (listed on the Price Inference tab).
**Edit-sheet conventions (the specialist's, read by Part 2):** every price in every tab is a plain number (12.95, format 0.00 — never `$12.95`, no `'` prefix needed). Dish Item + Modifier Summary: type `x`/`X` over a price = remove it (dark grey); type a price into an EMPTY cell = a new price, adds that size (vivid yellow); to MOVE a price, paste it into the empty cell and `x` the old one. Anything that is not a valid price (letters, comma, %, a negative dish price — modifier prices may be negative —, 1000+, 0 in an empty cell, 5× / a fifth of the system price: a misplaced decimal point — Part 1's own price that far off is red too, a likely misread —, or a new price at 10× / a tenth of the item's other prices) shows red text and Part 2 ignores it. Sorting or recolouring a tab is safe: Part 2 finds each row's baselines by a hidden row key and reads Part 1's changes from a hidden system-price mirror, never from the colour. A dish / modifier listed under two groups is ONE item: edit either copy — the edited copy wins over an untouched one; two copies edited to different prices are not applied. Only what Part 1 changed (blue/pink/purple) or the specialist edited is ever written — an untouched price never overwrites a newer live one. Strikethrough on a dish name (column B, whole or part) = make that dish permanently unavailable. **Dish Code tab** (when the restaurant or the paper has codes): the left block is each size's code (editable), the right block the code printed on the paper (blue = differs, yellow = the system has none, green = same); NOTHING is written unless the specialist puts a code in a left cell — copy a paper code over to accept it (a whole paper column pastes safely, even with its header: its empty cells change nothing), `x` removes a code, a code typed into an empty cell adds one; grey = the size has no price (a code needs one — a code typed there is red, and Part 2 applies it only if a price for that size is added on Dish Item too); red text = not a code (a line break, > 128 characters, a leading `=`, or only # - . and spaces). A code is read like Excel's TRIM (no-break spaces count as spaces; `1.0` stays `1.0`). Proposed from the paper: the OCR's `code`, or a number printed before the name only when it has a letter (`A5`) or a `.` / `)` after it (`12.` — `10 Fried Dumplings` is a count); a lunch-special code only on Lunch; two codes reaching one size (also through Order→Large or Small→Lunch routing) are asked (P-CODE), not proposed. Questionnaire column I **Notes → Wonka** = an instruction for Wonka on that row — Part 1 never writes there. Modifier Rule tab: 'by itself' (H) is a live link to the dish's Dish Item price (DELTA) or its By Itself row (ABSOLUTE) — edit the price there and Expected / Match? follow; a Price that is not a valid price (letters, `x`, comma, %, 1000+, 5× / a fifth of the live rule price — compare's own price too, a likely misread) shows red text and is not applied (negatives are fine on rules). Part 2 rounds a typed price like the sheet does (3.675 → 3.68).

## SCRIPT CATALOG (P1)
- `setup.sh` — `bash setup.sh`. Idempotent venv+openpyxl bootstrap.
- `wsheet_xlsx_bridge.py to-xlsx <tsv_dir> -o raw.xlsx` — each tab.tsv→sheet, cells verbatim str (no coercion).
- `action1_raw_to_2a.py <raw.xlsx> [-o]` — Raw→Menu Preview. Price cols = row2 `unit_price` markers. Include dish iff: in dish_group, exactly 1 root row, ≥1 non-empty price. "Select "-prefix modifier groups replicated per dish_group; orphans w/ prices at end; sections sorted reverse-alpha. Also writes an `absolute_pricing` tab: every $0.00 dish cell whose price lives on modifiers (priced modifier_rule rows for the dish = ABSOLUTE; group-level rows for its dish group only when a priced By Itself is among them or they price a REQUIRED choice — a group add-on like "Sauce / With +$1.00" is an upcharge; a required modifier group whose every item is priced, e.g. Seafood Boil; and — in a restaurant that prices dishes on modifier rules, i.e. some live $0.00 dish has priced rules holding its price (a By Itself, or a required choice) — every $0.00 Fried Specialties dish) — see G11. A `System Codes` tab (each size's `unit_code`, row-aligned with the price tab — action3 builds the Dish Code tab from it; not named `dish_code`, which would switch on action2's dormant code tie-break). And a `side_rules` tab for action2's missing-table warning: dishes priced with side-combo rules (a priced By Itself, or a priced side — fries / rice / lo mein / chow mein / mei fun / noodles; dish- or group-level — an add-on or a sushi topping is not a side table).
- `action2_ocr_to_2b_0625v2.py <ocr.json> <menu_preview.xlsx> [--dict <wonders.xlsx>] [-o]` — writes to ANY header variant col (no whitelist). Never writes a paper price onto an `absolute_pricing` cell: held in an `Absolute Held` tab → Questionnaire P-ABS (G11). Two different prices printed for one system size (the dish in two sections, an Order price routed onto a printed Large, a routed Small vs a lunch special) → neither written, listed in a `Price Conflicts` tab → Questionnaire P-PRICE. A printed price for a size the dish does not have (and cannot be routed — the dish has 2+ other sizes) → `Unplaced Prices` tab → Questionnaire P-SIZE (skipped when it equals the By Itself price of the dish's $0.00 size). Prices written as text in the OCR JSON ("$9.59") are read as numbers; anything else ("MP") is reported, never read. Printed dish codes (the item's `code`, or a printed prefix like `L15.`) go to the system size their price landed in — one number on a two-size row → both sizes, a Lunch-section `L26` → Lunch — in a `Paper Codes` tab; two different codes printed for one size → `Code Conflicts` (asked, not proposed). Passes EVERY multi-column section (one block each) to the `Fried Specialty Sides` tab and prints `Multi-column sections passed to Fried Specialty: N`. Prints `⚠ NO MULTI-COLUMN TABLE IN THE OCR JSON` when dishes the system prices with side-combo rules were read from the paper but no section has `side_pricing` — check the paper (Plain | w. … table?) and fix the OCR JSON before action3. Native POS-code match (dish_code tab, Bouncer-Logic bypass on split items) → fuzzy. Tier1 cleanse, bubble default_price fallback, 10-step name resolution, compound splitting, per-row section-aware size_based/lunch_based (Small→Lunch only when row has Lunch slot & no Small — Soup/White Rice keep Small), dual-column→size_based, section prefix/suffix, section aliasing.
- `ocr_sanity_check.py <ocr.json> [--strict]` — advisory pre-action2: Small>Large, whole-number ≥100 (dropped decimal; not for Party Tray), out-of-range, `uncertain:true`, no-price rows. Never changes prices. Default exit 0; `--strict` exits 1 if any flag.
- `action3_compare_and_merge.py <menu_preview.xlsx> <ocr_output.xlsx> [-o]` — Price Comparison Report. Tabs: Dish Item(blue=inc/pink=dec/green=confirmed-nochange), Modifier(hidden baseline), Summary, Questionnaire(A–H script: ID/Category/Dish/Current/Expected/Menu Price/Details; I = Notes → Wonka, left empty; sections P1 [+P1-TRAY when the restaurant has Party Tray prices], P-COLUMN, P-CODE, P-SIZE, P-PRICE, P-ABS [Details says the exact tab · row · column to edit], P2 — NO P3 / Additional / P5 / P6; NO dropdowns), Fried Specialty(if side_pricing; one block per section), Modifier Summary(deduped, excl all-$0 groups & $0 items). Hidden `_ref_` cols (baselines), Dish Item `_ref_sys_` cols (the system price — Part 2 reads Part 1's changes from these) and `_ref_key:group` / `_ref_key:name` (each row's key), right after the data so a sort keeps them with their rows; apricot CF on manual edits (numbers compared as numbers); ahead of it (Dish Item + Modifier Summary): dark grey on an `x`, red text on anything not a valid price (10 rules matching Part 2's parsers exactly — incl. 5× / a fifth of the system price and a new price at 10× / a tenth of the item's other prices; Dish Item trays exempt), vivid yellow on a price typed into an empty cell (each CF formula < 255 chars). Every price written as a plain number. Party Tray compared like any variant (v4.3). Dish Code tab (system code | printed code per size, see the conventions above). Does NOT write purple / Price Inference — that is the next script.
- `price_inference.py <menu_preview.xlsx> <ocr_output.xlsx> --report <report.xlsx> --mode apply` — EVERY restaurant, after action3, before §3b compare. Fills unprinted prices (V-GAP / D-GAP) from dish-group donors, + **T-TRAY**: unprinted Party Tray from the tray formula of the dish's OWN dish group (e.g. Large×5−$2), only when ≥70% of that group's tray rows fit ONE formula; a group too small / too mixed uses the whole-menu formula only if it fits ≥70% of the group's own trays, else its changed trays are asked (maintainer 2026-10-05: "be safe, per group"). **T0 same-price rules first:** General Tso / Orange / Sesame <Chicken|Beef|Shrimp> always the same price; a Healthy "Steam X" NOT on the paper menu = regular "X" when the old prices were the same; Chow Mein + Chop Suey are one cohort for T1. Never infers onto a $0.00 cell (free item or priced on modifiers), never from an `absolute_pricing` cell (G11). Writes purple Dish Item cells + Price Inference tab + Questionnaire P-TRAY + Summary AUTO-INFERENCE (no P6 section). A re-run first puts its earlier purple cells back to the system price (never a cell the specialist typed over) and never writes over a specialist's value; it writes only into a report row that is the same dish (a stale report is suggest-only). Script default is `--mode suggest` (no writes) — this workflow uses `--mode apply`. Details: `references/price-inference.md`.
- `modifier_rule_pricing.py` (multi-col only)
  - `preflight <raw.xlsx>` — MANDATORY G11 gate, must exit 0. Model is decided per (dish, variant) and listed: ABSOLUTE / DELTA / MIXED (both, e.g. China Village) = exit 0. DOUBLE_CHARGE (a dish/variant priced on dish_item AND its By Itself rule) / BROKEN = nonzero→STOP+escalate. Only dish-level By Itself rows count as anchors (a restaurant-wide `Plain` rule is not one); anchor = WHOLE modifier name after normalization (`Plain Fried Rice` is an upcharge, not an anchor). A priced GROUP-level By Itself rule on a dish that also has a dish_item price is a DOUBLE CHARGE too.
  - `compare <ocr.json> <raw.xlsx> --report <report.xlsx> [-o]` — REQUIRED --report writes INTO that workbook (one file, forbidden to make separate). Adds Modifier Rule tab (A–F edit cols + OCR validation + embedded crop @N1) + folds delta+propagation into Fried Specialty. Detection by structure (`side_pricing`), not name — EVERY side_pricing section. Every price is kept per (dish, variant): each paper row is attributed to ONE variant (its Plain price key, the dish's only variant, or a size in its name like "5pcs"), else `VARIANT UNKNOWN`, not applied; sizes the paper did not print keep their own prices. Each (dish, variant) uses its own model: DELTA → Delta=round(combo_total−plain,2); ABSOLUTE → side rule = full total and the paper Plain goes on the By Itself rule (dish_item stays $0). A combo row with no Plain takes it from the same dish's single-price row elsewhere on the menu (else ABSOLUTE: sides only; DELTA: `NO PLAIN`, not applied). Exact name match to any system dish first. A dish without rules of its own is left alone: callback flag `NO DISH RULES` when an enabled, priced group-level rule of its group prices one of the printed sides (one paper row never changes a whole group's rule), else a `NO SIDE RULES` note. A printed side that the dish has rules for, but none for that side → callback flag `NO RULE FOR SIDE` (names the group rule if one prices it). A printed row always keeps its own printed price. Propagation: same-dish old-price group (only when every printed member agrees — else unprinted members left + GROUP CONFLICT), then PRICE TWIN (group) then global PRICE TWIN; TWIN CONFLICT / PAPER CONFLICT (same dish printed differently in two sections) left at current price (not guessed). Validation: 'by itself' = live link (DELTA: the dish's Dish Item cell — the edited copy if the dish is in two groups; ABSOLUTE: its By Itself row's Price); Paper menu Total = the total actually printed (blank for derived rows); Expected = by-itself+price (DELTA) / price (ABSOLUTE); Match? N/A without a printed total. If the report has no Fried Specialty tab although the OCR JSON has a multi-column table, compare builds it and prints `!! DRIFT` (action2/action3 ran on a different JSON — re-run them). Hidden columns (found by label in Part 2): L `_ref_baseline` (compare's price), AD `_ref_live` (the live price at Part 1), AE `_ref_key` (the row's key). Fills each Questionnaire P-ABS "modifier rules" row with the exact Modifier Rule row of that dish's By Itself (column B, linked). Blocks DOUBLE_CHARGE/BROKEN like preflight. `--conflict` is ignored (G14). `with`/`w.`/`w ` prefix stripped safely (bare `w` must be followed by `.` or space). Does NOT modify Raw. Idempotent re-run. Also re-applies canon tab order (incl. Price Inference).
- `crop_section.py <img> -o crops/<n>.png [--title X][--next Y][--rows top|middle|bottom][--box L,T,R,B][--min-price-cols N][--sidecar][--debug]` — derives crop from content. Also usable per priced section for Opus vision (see ocr-prompt IMAGE PREPARATION). Optional embed target for compare.

## GUARDRAILS
- G1 NEVER write blank cells (incl code slots, group-gate FALSE rows).
- G2 NEVER add/remove rows — overwrite existing only.
- G3 Highlight: blue=increase, pink=decrease, green=confirmed-no-change, **purple=inferred (not printed — confirm on callback)**, dark grey=`x` (price to remove), vivid yellow=new price in an empty cell, red text=not a valid price (ignored). Prices are plain numbers everywhere. Party Tray (v4.3): printed → compared + written like any variant; unprinted → T-TRAY only (purple). Key tray prices `Party Tray`, never `Order`.
- G4 Use SYSTEM names + paper prices. Parse by header text, not position.
- G6 The report shows every price as a plain number (G3); the raw / live cells stay `$X.XX` — Part 2 writes that format back. Codes verbatim if ever present.
- G11 ABSOLUTE double-charge guard (model-aware, decided per (dish, variant) — a restaurant, even one dish, can mix both). DELTA: base on dish_item, no priced By-Itself row, side=upcharge (out_unit_price=combo_total−plain). ABSOLUTE: dish_item=$0, By-Itself row carries base, side=full total (out_unit_price=paper_total). Anchor = dish-level By-Itself row (aliases: By Itself/Plain/No Rice/No Side — whole name, normalized). A (dish,variant) priced on BOTH dish_item and its By-Itself rule = DOUBLE-CHARGE ERROR (blocks compare/preflight, nonzero). Never route around nonzero. **A $0.00 dish whose price lives on modifiers (`absolute_pricing`: dish-level rules, group-level rules with a priced By Itself or on a required choice, a required fully-priced group, or any $0.00 Fried Specialties dish in a restaurant that prices on modifier rules) is never given a paper or inferred dish_item price — held to P-ABS.**
- G12 No hand-authored numbers. Inference counts → `price_inference.py` stdout / `price_inference_summary.json` only. If a number isn't in this turn's tool output, don't write it.
- G13 Never skip multi-col analysis or claim it belongs to Part 2 — that is a critical failure. If OCR JSON has side_pricing, running modifier_rule_pricing compare is mandatory here.
- G14 Inferred prices: every purple cell / Price Inference row is a callback question (never present as if printed). Never widen the inference rules beyond the sanctioned ones — T-TRAY, and the maintainer's T0 same-price rules (Healthy: only a dish NOT on the paper) + Chow Mein/Chop Suey cohort (2026-09-30): no cross-variant delta, no resolving a cohort/twin/price-group/paper/family conflict by picking a side, no hand-filling SKIPPED rows.

## QUESTIONNAIRE CATS (Questionnaire sheet, dishes)
P1=on paper, unmatched; **P1-TRAY** (first P1 row, only when the restaurant has Party Tray prices) = confirm or update the Party Tray prices. P-COLUMN=variant col blank in system row→routed to only populated col (verify). **P-SIZE=the paper prints a size the dish does not have (not compared): its Details list the dish's sizes — edit the matching one, or type the new size into its empty cell.** **P-ABS=paper price NOT written onto a $0.00 dish whose price lives on modifiers (G11); its Details column says exactly where to edit instead — `EDIT → 'Modifier Rule' tab · row N · column B` (the By Itself row) or `EDIT → 'Modifier Summary' tab · rows a–b (group '<choice>') · column '<size>' (letter)` (a required choice), linked. No such row / tab → it says to write the price in Notes → Wonka on that row.** **P-PRICE=the paper prints two different prices for one size (a dish in two sections, an Order price routed onto a printed Large, a routed Small vs a lunch special): neither is written — ask the client which is right and type it into Dish Item.** P2=decreases (rare, verify). **P-TRAY=Party Tray callbacks: one P-TRAY-0 row per dish group states its formula (or why none), then each derived / outlier / unresolved tray — a dish under two groups is derived only when every group derives the same tray, else asked.** **P-CODE=dish codes: a pointer to the Dish Code tab when printed codes differ from / are missing in the system, and one row per size the paper printed two different codes for.** Removed (2026-09-30): P3, Additional Questions, P5, P6 — inferences are on the Price Inference tab. Every row: column I Notes → Wonka is the specialist's. A dish code is never written by Part 1 — Part 2 writes only codes the specialist put in the Dish Code tab (G1).

## OCR RULES (ocr-prompt.md core)
JSON schema = full schema at bottom of `references/ocr-prompt.md` (emit exactly), including optional `uncertain` / `uncertain_note`.
Capture EVERY item; names exact as printed (script normalizes w./&/hyphen/plural/word-flip). Variant key must match a Menu Preview header. Note codes (L1,C1). Multi-col: capture FULL bordered block out to ruled border incl right-most col; preserve with/w. verbatim; capture every printed price incl partial rows (null only for genuinely blank cols); read ragged rows by dotted leaders not x-position; side_prices:null ONLY when Plain-only & truly no side prices; self-check #side_prices rows == #paper rows w/ >1 price. Strip decorative tokens ((4),(6),reading aids) unless disambiguating. Digit care: .25/.75, .00/.50, 8/9, 0/6, 1/7, 3/8, 5/6, 9/4; whole-number ≥100 is a dropped decimal until proven. Prices ~never decrease (re-verify). Count price cols per section first; emit one item per printed row (`null` not skip). Flag uncertain instead of guessing. Crop per section for Opus (~2576px long edge) — do NOT feed system prices into the read. Compound auto-expansion (parenthetical, or, slash-dual, comma multi-protein, bare-protein-under-header→prepend section [or emit `<Protein> <SectionWord>` for suffix sections], choice-of-sauce→one dish/choice).
