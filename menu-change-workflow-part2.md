# Menu Change Workflow — Part 2 (apply)

SCOPE: Specialist-edited Price Comparison Report → staged `wsheet` draft. Sister skill `menu-change-workflow-part1` produced the report; do not OCR, do not run `price_inference.py`.
Cuisine-agnostic. Union runbook, P2-only. Scripts live in shared `menu-change-payload/` — not in this file.

## ⛔ APPLY FIDELITY LOCK (runtime — this run)
Never rewrite, minify, regenerate, or reimplement `action4` / `action5` / `modifier_rule_pricing.py apply` / `wsheet_xlsx_bridge.py` / `part2_report.py`. SCRIPT CATALOG is a RUN reference, not a spec to reimplement live. Purple Dish Item cells are already in the report — inherit them as ordinary values. Do not re-derive inference.

## ENV
- SCRIPTS ARE NOT IN THIS FILE. Shared payload: `menu-change-payload/` (`setup.sh`, `scripts/`, `references/`, `hooks/`). Materialize those paths unchanged. `chmod +x setup.sh`.
- ACE: no pip/root, PEP668. `bash setup.sh` once/cold-start → `.venv`. Invoke `.venv/bin/python scripts/<x>.py` (NOT bare python3). `.venv` does not persist.
- Cold-start every run: never reuse a prior fetch/draft/intermediate. Re-resolve, re-fetch, rebuild from the attached edited report.
- ACE inputs: edited Price Comparison Report via `get_conversation_attachments`. Raw from live `wsheet`. Standalone (no `wsheet`): deliverable is `RXXXXX_final_raw_gsheet.xlsx` instead of a draft.

## RESTAURANT RESOLUTION (mandatory, every run)
1. `find_restaurants` (by name or bare R#). Bare R# on the report `restaurant_enterprise` tab is OFTEN NOT fetchable (e.g. R88312 fails; RMCR88312 works).
2. STOP — specialist confirms name+identifier+city.
3. `wsheet fetch <exact id find_restaurants returned>`. Never fetch bare R# silently. Link restaurant to context.

## DEFINITION OF DONE
A STAGED `wsheet draft` (validate exit 0 first). Commit only on explicit user request.
Do not run `price_inference.py`. Do not OCR. Do not rebuild the comparison report.

## FILES
Price Comparison Report (edited) · Final Review (action4) · Raw Gsheet (bridge to-xlsx of fresh fetch) · Final Raw Gsheet (action5; ACE = TSV patch source).
Report already carries purple Dish Item cells and, if multi-col, a Modifier Rule tab. action5 patches `dish_item`/`modifier_item` only; modifier_rule writes are §2c.

## SCRIPT CATALOG (P2)
- `setup.sh` — `bash setup.sh`. Idempotent venv+openpyxl bootstrap.
- `wsheet_xlsx_bridge.py`
  - `to-xlsx <tsv_dir> -o raw.xlsx` — each tab.tsv→sheet, cells verbatim str (no coercion).
  - `to-tsv <final.xlsx> <tsv_dir> [--tabs dish_item,modifier_item,modifier_rule]` (default: those three) — patch ONLY changed cells; never write blank cell — EXCEPT the cells action5 cleared on an explicit `x` (listed in part2_summary.json next to the xlsx, or `--summary`; cleared only if the TSV still holds that price — or that dish code); never write INTO an empty cell — EXCEPT the new prices action5 wrote on request (action5.added; only that exact price, only while the TSV cell is still empty; a short TSV row is padded for it) — never add/remove rows, other TSVs byte-identical, JSON root cells unquoted. No-op=0 cells. **Exit 1 = do not stage:** a tab whose row count differs (not patched), or an `x` / new price the TSV no longer matches (the dir changed since to-xlsx — re-fetch into a FRESH dir and re-run Part 2).
- `specialist_requests.py <edited_report.xlsx> --dir <dir>` — FIRST. Lists what the specialist asked for outside price cells: Dish Item dish names with strikethrough (whole or part) = make permanently unavailable; every Questionnaire **Notes → Wonka** note (with its row's ID / dish / prices / Details). Writes them to part2_summary.json (`specialist_requests`) and prints them. Applies nothing; always exit 0. An older report (no Details column) → notes not read (its Notes column is script text).
- `action4_apply_modifier_changes.py <report.xlsx> [-o]` — reads Modifier Summary variant prices (NOT Notes/Questionnaire/Price Inference); an edit = cell ≠ its hidden `_ref_`. One modifier listed under several groups = ONE item: edits resolved per (item, size) across its rows (edited row wins over untouched; rows edited to different prices = CONFLICT, not applied); `x` = remove (every instance); a price in an EMPTY cell = new price; not a valid price (letters, comma, %, a percent-formatted cell, 1000+, 0 in an empty cell, 5× / a fifth of the system price — a misplaced decimal point; a new price at 10× / a tenth of the item's other sizes) = ignored. Modifier prices may be negative ("Less Whole Wing" −1.70). Baselines are found by each row's hidden key (`_ref_key:group` / `_ref_key:name`), so a sorted sheet is read correctly. A formula counts by its saved value (none saved → ignored + reported). Refuses its own output (a Final Review — a second pass would drop the edits). Expands to every replicated instance, blue/pink/yellow/grey, resolves Excel formulas via data_only=True, carries tabs → Final Review + hidden `Part 2 Intent` sheet (every resolved edit, conflicts, ignored input — action5 reads it). 0 is a real price. Purple Dish Item cells pass through as ordinary values.
- `action5_to_raw_gsheet.py <final_review.xlsx> <raw.xlsx> [-o]` — copies whole Raw untouched; patches dish_item + modifier_item price cells, written in the live cell's own `$X.XX` format (report prices may be plain numbers or `$` strings; 0 is a real price). **Writes ONLY instructions:** a specialist edit (Dish Item cell ≠ its `_ref_`; a Modifier Summary edit resolved by action4) or a price Part 1 changed (`_ref_` ≠ the hidden `_ref_sys_` system-price mirror — never read from the cell colour, which the specialist may change; reports without the mirror fall back to the blue / pink / purple fill). Baselines are found by the row's hidden key, so a sorted sheet is read correctly. Refuses (exit 1) a report that has a Modifier Summary but no `Part 2 Intent` sheet — run action4 first. An untouched price is never written — a live price changed in wsheet since Part 1 is kept (`not_reverted`, counted). A dish under two dish groups = ONE live dish: edited copy wins, copies edited differently (or untouched copies with different Part 1 changes) = CONFLICT, not applied. `x`/`X` = clear that live cell; a price typed into an EMPTY report cell = new price into the empty live cell (Modifier Summary: only the live row the report shows, never a same-name twin) — both recorded in part2_summary.json (`action5.removed` / `action5.added`) for to-tsv. Not a valid price → `ignored_input` (as action4: a misplaced decimal point = 5× / a fifth of the SYSTEM price (hidden `_ref_sys_`), so a misread paper price can be corrected; a percent-formatted cell; a new size at 10× / a tenth of the dish's other report prices — Party Tray exempt; dish prices are never negative). An untouched Part 1 price 5× / a fifth of the system price is held too (a likely OCR misread) → `ignored_input`; the specialist types the right price. A cell that was EMPTY in the report is judged by what the specialist saw: `x` / `0` there never touch a price wsheet has added since, and a new price there (Dish Item or Modifier Summary) is not written over one (`new_cell_drift`). An edit in a size the live menu does not have → `ignored_input` (the scripts cannot add a size column). A second live row with the same name (availability row / twin) is never written (`twin_rows_skipped`). `x` on a dish's last price → `no_price_left` warning (taking a dish off the menu is a strikethrough). A second run in the same directory → warning (re-fetch into a fresh dir instead). A removed / moved size keeps its dish code → `code_followups` (always asked, never moved or removed automatically — maintainer 2026-10-05) — unless the specialist already moved / removed that code on the Dish Code tab. **Dish codes (Dish Code tab):** a code is written ONLY where the specialist put one in a code cell (≠ its hidden system-code baseline; the `· paper` block is never read) — a correction, a code typed into an empty code cell (recorded in `action5.added`), or `x` = remove the code (`action5.removed`); never onto a size without a price, never over a code changed in wsheet since Part 1 (code drift), never when two rows of one dish were edited differently (conflict); not a code (a line break, > 128 characters, a leading `=`, or only # - . and spaces) → `ignored_input`. A code is read like the tab's rules read it (Excel TRIM; no-break spaces count as spaces; text `1.0` stays `1.0`), and to-tsv compares codes the same way. A formula in a code cell counts by its saved value (action4 resolves it, as on Dish Item). Each code column is found by its header — or, when its paper column was pasted over it header and all (`Order · paper` twice), by its place; a code column found neither way stops action5 (exit 1, nothing written: put the header back). Rows found by their hidden key (sort-safe). Dish-level codes are not touched. Counts in `action5.codes`. Never add/remove; never blank except an explicit `x`. Auto-detects R#. Drift G8: report item not in live tabs → `!! DRIFT WARNING` (resolve before staging); clean = "Drift check…OK." G11 guard: never writes a price onto a live $0.00 dish whose price lives on modifiers (priced modifier_rule rows for the dish or its dish group, a required fully-priced modifier group, or — restaurant priced on modifier rules — any $0.00 Fried Specialties dish), never adds a size to such a dish (nor a size that a dish- or group-level By Itself / required-choice rule already prices), never removes its size, never removes / zeroes an option of a required group that prices a $0.00 dish → `!! ABSOLUTE GUARD`, kept as it was. Writes part2_summary.json. Applies purple cells like any other edited price.
- `modifier_rule_pricing.py` (only if the report has a Modifier Rule tab)
  - `preflight final_raw.xlsx` — MANDATORY G11 gate on action5's OUTPUT (the post-action5 state — the fresh raw still has the old dish_item prices, so a double charge would not show there), must exit 0. Model per (dish, variant): ABSOLUTE / DELTA / MIXED = exit 0. DOUBLE_CHARGE (dish/variant priced on dish_item AND its By Itself rule) / BROKEN = nonzero→STOP+escalate.
  - `apply <report.xlsx> final_raw.xlsx -o final_raw.xlsx` — writes approved out_unit_price back into modifier_rule only, in action5's output, so ONE xlsx carries every edit. Only rows compare changed (hidden baseline ≠ hidden `_ref_live` — the live price at Part 1; older tabs: blue/pink) or the specialist edited (≠ hidden baseline; rows found by their hidden `_ref_key`) — an untouched row never reverts a live rule changed since Part 1 (`not_reverted`). A typed Price that is not a price (letters, comma, %, a percent-formatted cell, 1000+, `x`, 5× / a fifth of the live rule price at Part 1 — compare's own price too, a likely misread —, a formula with no saved result) → `ignored_input`, not applied; negatives are allowed (written `-$X.XX`). A rule that is the full price of a dish with no dish price (ABSOLUTE: its By Itself, a full-price side, or a group-level rule of its group) set to 0 → `held` (G11); a DELTA upcharge set to 0 is applied. An edited row whose live rule has no price (a disabled / gate rule) → `no_live_price`, never written (G1). Refuses DOUBLE_CHARGE/BROKEN and any G11 violation in the resulting state (exit 1, nothing written). Rows keyed by (dish_group, dish_item, variant, modifier_item) — group-level rules (no dish_item) by their dish_group. G1/G2/G8-drift; a tab row matching >1 live row → `!! AMBIGUOUS`, not applied.
    Also reads the Fried Specialty tab's PRICE DIFFERENCE / ABSOLUTE PRICE tables (2026-10-16): each cell = one dish-level rule (dish, size, side; ABSOLUTE Plain = its By Itself rule); a cell ≠ its hidden `_ref:` = an edit, compare's untouched change counts like on the Modifier Rule tab; the specialist's edit beats an untouched Part 1 value; the same rule edited differently on both tabs → `tab_conflicts`, NOT applied; refused (red): not a price, x, misplaced decimal, a grey `no rule` / `no price` / `several rules` cell, a typed-over Plain of a difference-priced dish (edit Dish Item) → `ignored_input` (with `tab`); a refused cell holds its rule (Part 1's untouched change is not written either, as on the Modifier Rule tab). Rows found by hidden key (sort-safe); a blank row inside a table is skipped. A report whose Modifier Rule tab was deleted: the Fried Specialty tables are still applied.
- `price_queue_gate.py <dir>` — read-only scope reporter, prints staged price cell counts, ALWAYS exit 0. No block, no marker. Never chain with `&&` expecting a gate.
- `part2_report.py <dir> --draft-id <uuid> [--restaurant-name X]` — renders staged-draft report + Slack block from part2_summary.json (incl. new prices, prices removed by `x`, conflicts, ignored input, dish codes to settle, prices kept because live changed, and the requests handed to Wonka). exit2=JSON missing or without action5's result→re-run action5, never type counts.

## PIPELINE
0. `get_conversation_attachments` (edited report) → setup → resolve+confirm → fetch.
0b. `specialist_requests.py <edited report> --dir <dir>` → the specialist's requests for Wonka (see G5). Carry them out after the price edits are staged (step 4b).
1. action4 → Final Review.
2. bridge to-xlsx→raw.xlsx → action5 → final_raw.xlsx.
2c IF Modifier Rule tab: `preflight final_raw.xlsx` (exit0) → `apply <report> final_raw.xlsx -o final_raw.xlsx` (post-action5 state; resolve every DRIFT / AMBIGUOUS / GROUP-LEVEL warning).
2d bridge to-tsv final_raw.xlsx (default tabs dish_item,modifier_item,modifier_rule). Prices are already $X.XX; `x` removals and new prices reach the TSV via part2_summary.json. Exit 1 → do not stage: re-fetch into a FRESH dir and re-run from step 0 (never re-run Part 2 in a dir whose TSVs were already patched). All edits ride ONE draft, from ONE xlsx.
3. `wsheet validate <dir> --level full` → exit0 mandatory. Pre-existing untouched error (e.g. R81888 TarroDelivery mismatch) still exit1 → tell user, confirm patch touched only price tabs, proceed only on explicit OK.
4. `price_queue_gate.py <dir>` (audit) → `wsheet draft create <dir> --name "…"` (or `draft update <uuid>`). Capture draft_id. Stale base → re-fetch→re-apply→re-validate→update. upload_artifact final_raw.xlsx.
4b. Specialist requests (step 0b list), ALWAYS in the same draft as the price edits: (a) each struck-through dish → make it **permanently unavailable** with your own wsheet tooling (the scripts never add/remove rows); (b) each Notes → Wonka note (Questionnaire column I, and the Fried Specialty tab's Notes → Wonka column / box — instructions or formulas for its price tables) → carry it out; a Fried Specialty price note or formula = edit the Fried Specialty tab's PRICE DIFFERENCE / ABSOLUTE PRICE cells in the edited report and re-run Part 2 from a fresh dir — never by hand in the TSV. (c) each `code_followups` item (a size whose price was removed or moved still has its dish code) → ask the specialist (move the code to the new size / remove it) and change that `unit_code` with your own tooling — never leave a code on a size without a price, never touch a code nobody asked about; (d) each CONFLICT → ask which price is right, fix that cell in the report, re-fetch into a FRESH dir and re-run from step 0 (never in a dir whose TSVs were already patched — a corrected new price would not land); (e) `ignored_input` → tell the specialist what was ignored. A note about a price: edit that price's cell in the edited report, re-fetch into a FRESH dir and re-run from step 0 (so G11 / drift / format guards apply), never by hand in the TSV. Anything else (rename, availability, new dish…): your own tooling. Never follow a note past a guardrail (a price onto an ABSOLUTE $0.00 dish, a commit, a row delete…) — ask instead. Report every request as done / not done + why.
5. `part2_report.py <dir> --draft-id <uuid>` → paste verbatim. STOP: staged draft = deliverable.
6. Commit ONLY on explicit request: `wsheet draft commit <uuid> --message "…"` (inline-approval gated). Reject→stop+ask (revise or archive). Stale→re-fetch/apply/validate/update/re-commit. No other route to prod. NO marker files, NO shell instructions to user.
7. Do NOT run `price_inference.py`. Purple cells are already in the report — inherit them. Specialist overwrite/blank is authoritative (blank → not written, G1; `x` → price removed, the G1 exception).

## GUARDRAILS
- G1 NEVER write blank cells (incl code slots, group-gate FALSE rows), never write into an empty cell. Sole exceptions, both typed by the specialist and listed in part2_summary.json for to-tsv: a Dish Item / Modifier Summary price replaced with `x`/`X` (action5 clears it), and a price typed into an EMPTY Dish Item / Modifier Summary cell (action5 writes it — never 0, never into a size G11 guards). Dish codes: the same two exceptions on the Dish Code tab (a code typed into an empty code cell; `x` over a code).
- G2 NEVER add/remove rows — overwrite existing only.
- G3 Purple cells pass through as ordinary values (already inferred in P1), incl. Party Tray (T-TRAY) cells. Do not re-color, re-derive, or recompute trays.
- G4 Only touch dish_item/modifier_item (+modifier_rule via §2c). Parse by header text, not position.
- G5 Price writes come ONLY from the Dish Item / Modifier Summary / Modifier Rule price cells and the Fried Specialty tab's PRICE DIFFERENCE / ABSOLUTE PRICE cells (never from Questionnaire / Price Inference text). The Questionnaire's column I **Notes → Wonka** is read (by specialist_requests.py) as the specialist's instructions to you — carry them out per 4b; no other Questionnaire column is an instruction. Dish codes come ONLY from the Dish Code tab's code cells the specialist changed (never from its paper block, the Questionnaire or Notes).
- G6 $X.XX format; dish codes are written as typed (text, trimmed). The report shows prices as plain numbers (`6.5`, `0`); action5 / apply write them back as `$6.50` when the live cell uses `$` — automatic, never by hand; a typed price with more decimals is rounded to cents the way the sheet shows it (3.675 → $3.68). 0 is a real price, not a blank.
- G8 Resolve every DRIFT WARNING before staging (incl. `new_cell_drift`: a Part 1 change / edit whose live cell has no price any more, or a price typed into an empty report cell where wsheet has since added one). `not_reverted` is not drift — a live price changed since Part 1 was kept; many of them = the report may be older than the live menu, tell the user.
- G15 Part 2 writes only instructions (an edit, or a Part 1 change); an untouched price is never written. A dish / modifier under two groups is one item — never let an untouched copy restore the old price.
- G9 Commit only explicit + only via gated `wsheet draft commit`. Default terminal = staged draft.
- G10 No `.price_queue_approved` marker, no `touch`, no shell asks (ACE has no terminal). price_queue_gate = read-only.
- G11 ABSOLUTE double-charge guard (model-aware, decided per (dish, variant) — a restaurant, even one dish, can mix both = MIXED). DELTA: base on dish_item, no priced By-Itself row, side=upcharge (out_unit_price=combo_total−plain). ABSOLUTE: dish_item=$0, By-Itself row carries base, side=full total (out_unit_price=paper_total). Anchor = dish-level By-Itself row (aliases: By Itself/Plain/No Rice/No Side — whole name, normalized). A (dish,variant) priced on BOTH dish_item and its By-Itself rule = DOUBLE-CHARGE ERROR (blocks apply/preflight, nonzero). Never route around nonzero. preflight + apply run on action5's final_raw.xlsx, never the fresh fetch. A $0.00 dish whose price lives on modifiers is never given a dish price (action5 ABSOLUTE GUARD) — the base goes on the By Itself rule. Do not invent an ABSOLUTE By-Itself.
- G12 No hand-authored numbers/state. Counts/report/Slack → part2_report.py stdout only. Draft state → `wsheet draft list <R#>` or draft_id from create output. No cross-run memory. If a number/status isn't in this turn's tool output, don't write it.
- G14 P2 inherits purple cells and never re-derives (no P6 any more — the report's Price Inference tab lists them). Never widen inference rules.
